## 首次外层启动器失败记录

首次 ZIP 外层启动器使用 `git show` 将 Git Blob读成 PowerShell 字符串，再通过 `WriteAllLines` 写入临时脚本。Windows PowerShell 5.1 的文本往返破坏了 UTF-8 中文和部分内容，导致正式部署脚本在解析阶段报错。

该次失败发生在正式部署脚本开始运行之前：

- 没有停止 `LOLDataSystem`；
- 没有 checkout 新提交；
- 没有修改配置或状态；
- 没有进入正式备份或正式回滚流程；
- 本地仓库只完成 fetch 和 Git 对象整理。

修复后的 `ops\Launch-LapiQueryHardening.ps1`：

1. 启动器自身为纯 ASCII；
2. 使用 `git archive --format=zip` 从精确提交按字节导出三个正式脚本；
3. 使用 `Expand-Archive` 解包；
4. 在停止服务前使用 PowerShell Parser 校验三个脚本；
5. 禁止 `WriteAllLines` 和 `git show` 文本重写。

CI 真实执行 `git archive`，逐字节确认导出内容与仓库文件一致。

## 工具

### 安全启动

```powershell
ops\Launch-LapiQueryHardening.ps1
```

### 部署

```powershell
ops\Deploy-LapiQueryHardening.ps1
```

执行顺序：

1. 要求管理员权限；
2. 校验 `origin`；
3. 拒绝已跟踪文件脏工作区；
4. 拉取发布分支；
5. 校验调用方提供的精确目标提交；
6. 校验生产祖先和当前本地提交祖先关系；
7. 自动识别 Windows 服务；
8. 创建受限 ACL 备份目录；
9. 在停服务前导出独立回滚脚本；
10. 备份本机环境文件、build-info、蓝奏配置、状态和查询快照；
11. 停止服务；
12. 使用 detached HEAD 切换目标提交，不移动原生产分支；
13. 安装依赖并运行完整单元测试；
14. 生成干净的 `build-info.json`；
15. 启动服务；
16. 执行新旧接口、协议、观测和快照验收；
17. 写入部署记录和验收报告；
18. 任一关键步骤失败时自动回滚。

### 回滚

```powershell

```

回滚不依赖远端分支移动，直接恢复部署记录中的 `previous_commit`，恢复本机文件，重新安装旧版本依赖并验证：

- 服务重新运行；
- `/livez` 和 `/readyz` 为 HTTP 200；
- `/build-info` 精确等于旧提交。
