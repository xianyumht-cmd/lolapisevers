## PowerShell 5.1 compatibility incident

Two operator attempts stopped during preflight before the formal deployment script executed.

1. The first wrapper used `git show` plus `WriteAllLines`, corrupting UTF-8 text.
2. The second wrapper correctly preserved Git bytes, but Windows PowerShell 5.1 interpreted an UTF-8-without-BOM deployment script using the local ANSI code page.

Neither attempt stopped `LOLDataSystem`, checked out a new commit, changed production configuration, or entered the formal backup/rollback phase.

The permanent fix is to keep every release PowerShell script ASCII-only. CI now directly invokes `powershell.exe` to parse all four scripts and also verifies that `git archive` preserves the exact bytes.

## Deployment sequence

1. Require administrator privileges.
2. Validate `origin` and the exact target commit.
3. Reject tracked local changes.
4. Validate production ancestry and current local ancestry.
5. Resolve the Windows service.
6. Create a restricted-ACL backup directory.
7. Copy the rollback tool before stopping the service.
8. Back up local environment, build-info, Lanzou configuration/state, and query snapshots.
9. Stop the service.
10. Check out the pinned release using detached HEAD.
11. Install dependencies and run the full test suite.
12. Generate build-info.
13. Start the service.
14. Verify old endpoints, new delivery/observability endpoints, and snapshot creation.
15. Write deployment and verification evidence.
16. Automatically roll back after any critical failure that occurs after the service is stopped.
