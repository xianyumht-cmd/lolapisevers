## 已修复的 29 个代码 Bug

### GroupGuard 查询、举报和消息协议

| ID | 修复结果 |
|---|---|
| `GG-001` | 并发查询的合并键加入请求方法、完整 URL、请求体和影响响应的请求头。查询不同账号时会分别请求上游，不再共享另一个账号的结果。 |
| `GG-002` | 举报幂等记录保存完整请求指纹。同一 `request_id` 配合同一内容才返回重复成功；同一编号配不同账号或内容直接返回 HTTP 409。 |
| `GG-003` | 举报接口拒绝空 `request_id`，官方客户端不再自动生成新的举报编号。 |
| `GG-004` | 请求编号改为严格校验，不再把空格、`@` 等不同字符统一替换成 `-`，消除编号碰撞。 |
| `GG-005` | 服务端和官方客户端共用同一套功能别名规范化规则，`ban`、`查封号` 等别名不会再触发 `feature_mismatch`。 |
| `GG-006` | 合并转发超过 32 个节点时明确报错，不再直接丢掉第 33 个节点后的内容。 |
| `GG-007` | 文本、图片、Base64、转发节点和总响应大小统一使用共享协议限制；服务端不再生成官方客户端必然拒绝的响应。 |
| `GG-008` | 官方客户端改成流式读取并在下载过程中执行大小限制；超过上限立即终止，不再先完整载入内存。 |

### 骗子、同行记录

| ID | 修复结果 |
|---|---|
| `CR-001` | 普通查询只更新 `last_checked_at`，不再修改代表内容变化时间的 `updated_at`。 |

### 动态查询和主接口安全

| ID | 修复结果 |
|---|---|
| `DYN-001` | 每一次 HTTP 跳转都重新校验目标地址，连接固定到校验后的公网 IP，并拒绝本机、局域网、链路本地和保留地址；响应硬限制为 1 MiB。 |
| `WEB-001` | 举报写入接口增加 `GROUPGUARD_WRITE_TOKEN` 鉴权；未配置 token 时只接受操作系统确认的本机连接，局域网设备不能匿名写入。 |
| `WEB-002` | SO1 人工登录接口增加管理鉴权和冷却时间，未授权设备不能启动浏览器登录流程。 |
| `WEB-003` | 外部接口响应改成分块读取并设置硬上限，超大响应不会再被完整读入内存。 |
| `SEC-001` | 管理审计日志加入文件锁、自动轮转和尾部读取；日志不会无限增长，页面也不会一次读入整个历史文件。 |

### SO1 和健康检查

| ID | 修复结果 |
|---|---|
| `SO1-002` | 移除进程级全局 `So1Client` 单例；每个配置实例使用自己的账号、密码、超时、浏览器和并发锁。 |
| `HLTH-001` | SO1 健康检查增加登录状态验证，不再只检查浏览器进程是否仍然连接。 |

### 蓝奏监控、WebUI 和管理工具

| ID | 修复结果 |
|---|---|
| `LZ-001` | `/notify/test` 和 `/test-push` 都调用实际存在的 `send_test_event`；两个 WebUI 的测试推送恢复正常。 |
| `LZ-002` | 加载配置时拒绝空监控 ID 和重复监控 ID，监控项不会再互相覆盖。 |
| `LZ-003` | `scan_on_start=false` 时使用明确的“等待首次定时扫描”状态，不再把正常等待判为服务故障。 |
| `LZ-004` | 布尔值、整数、浮点数和 HTTP 方法改为严格解析；字符串 `false` 不再被当成 `true`，非法方法直接报错。 |
| `ADMIN-001` | 诊断工具读取实际配置的端口、平台路径和当前日志文件，不再固定使用 5001、6178、3306 和 Windows 虚拟环境路径。 |
| `ADMIN-002` | 管理页面内部调试请求自动转发 `WEBUI_ADMIN_TOKEN`，开启管理密码后仍能调用受保护接口。 |
| `API-001` | 蓝奏配置校验错误统一返回 HTTP 400 和具体错误说明，不再返回无法判断原因的 HTTP 500。 |
