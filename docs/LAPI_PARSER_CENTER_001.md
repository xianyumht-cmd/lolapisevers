# LAPI-PARSER-CENTER-001

## 目标

把 `lolapisevers` 中直接访问第三方 API 的功能统一迁移到可配置的请求与响应解析系统。GroupGuard 插件只负责命令识别、参数传递与结果交付；第三方请求、字段解析、命中判定、缓存、降级与最终文本由 Windows 内网接口完成。

## 用户可见输出原则

群消息、转发消息和图片不得出现第三方域名、Provider 名称、`by` 字段或“接口来源”。管理员调试页面可以查看脱敏后的请求与原始响应，但 Token、Cookie、Authorization、API Key 和密码不得返回浏览器或写入日志。

## 第一阶段

1. 建立通用请求构造器，支持 GET、POST、Query、Headers、Form、JSON Body、参数占位符和 Secret 引用。
2. 建立通用响应解析器，支持 JSON 路径、多候选路径、值转换、条件判定、数组记录和模板渲染。
3. 修复封号查询丢失 `ban_reason` 的生产问题。
4. 在 6178 增加解析中心管理 API 与独立 WebUI 页面。
5. 配置默认不接管生产流量；现有 `LOL_BAN_PROVIDERS_JSON` 保持兼容。
6. 保存采用 Schema 校验、测试预览、备份和原子替换。

## 第二阶段

将骗子查询和同行查询迁移到通用解析器，替代当前固定字段和关键字猜测逻辑；支持多条举报记录、原因、时间、证据、金额和状态的可配置解析与合并去重。

## 第三阶段

将举报骗子和举报同行扩展为“本地可靠落盘 + 可配置第三方提交”。支持案件号、审核状态、回执说明、失败待补交和幂等控制。查询 Provider 和举报 Provider 使用不同策略，避免重复举报。

## 封号首个验收样例

输入：

```text
查封号 97077000
```

必须包含：

```text
封禁原因：游戏环境异常：检测到违规软件加载
```

不得包含：

```text
q.lolmap.cn
Provider
接口来源
by
```

机器可读计划见 `docs/LAPI_PARSER_CENTER_001_PLAN.json`。
