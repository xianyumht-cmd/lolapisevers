# 全查询跨渠道服务边界（强制规则）

> 状态：规范性文档（normative）  
> 计划：`GGK-ALL-QUERY-HUB-20260729`  
> 服务实现：`xianyumht-cmd/lolapisevers`  
> 当前客户端：SnowLuma / GroupGuard  
> 未来客户端：官方机器人及其他经过授权的平台适配层

## 1. 服务与客户端的永久边界

`lolapisevers` 是所有内置业务查询的渠道无关业务中心，也是唯一允许接触业务公网 Provider、Provider 凭据和共享业务数据库的组件。

任何客户端都只能：

1. 识别平台命令；
2. 提取最小原始参数；
3. 执行平台权限、功能开关和限流；
4. 生成请求 ID；
5. 调用内网查询协议；
6. 严格校验响应；
7. 执行对应平台的最终发送动作。

所有客户端都禁止：

- 访问业务公网 Provider；
- 保存 Provider URL、Token、Cookie、Key；
- 解析业务 JSON 或 HTML；
- 维护业务别名、状态判断、排序、评分、分页或推荐规则；
- 决定图片、文字、合并转发的业务降级；
- 合并多个 Provider 结果；
- 在服务失败时使用公网备用链路；
- 维护需要在多个客户端间共享的业务事实源。

## 3. 协议要求

当前协议：

```text
groupguard-query-delivery.v1
```

协议名称中的 `groupguard` 是历史命名，不表示服务与 GroupGuard 绑定。服务端实现必须保持渠道无关，响应只能描述最终交付内容和安全元数据，不能包含 OneBot 专属对象。

客户端将协议中的通用文本、图片、转发节点转换为自身平台动作。未来如需升级协议，必须保持版本化和旧客户端兼容窗口，禁止复制业务实现形成多套接口。

## 4. 查询与写入

查询使用最终交付协议。举报类写入必须另设经过鉴权的共享写入接口，并具备：

- 幂等键；
- 调用方身份；
- 字段长度和格式校验；
- 限流；
- 去重；
- 审计；
- 可回滚数据迁移。

SnowLuma 和官方机器人必须写入同一个风险数据库，不得各自维护独立骗子/同行事实源。

## 5. 配置和秘密

Provider 秘密只允许存在于 Windows 服务主机的受限本机配置。客户端配置只能包含：

- 内网 API Base；
- 非秘密的超时和平台发送能力；
- 平台自身认证信息。

客户端 WebUI 不得继续提供第三方 Provider Token、Cookie、Key 或公网业务 URL 的配置入口。

## 6. 发布门禁

每个 feature 的发布顺序固定为：

```text
服务代码与测试
  -> 服务生产部署
  -> 服务真人或故障注入验收
  -> 客户端代码与测试
  -> 客户端部署
  -> 平台真人验收
```

代码门禁必须验证：

- 客户端运行路径没有公网业务域名；
- 客户端一次命令只调用一次内网协议；
- 网络或协议失败不产生第二次或公网请求；
- 管理测试器和正式命令复用同一服务函数；
- SnowLuma 与官方机器人可以通过同一 fixture 验证；
- 生产已验收 feature 不因后续批次退回插件业务处理。
